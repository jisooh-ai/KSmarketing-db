# 마케팅 퍼포먼스 DB — MVP 적용 가이드

구성 파일 3개
- `supabase_setup.sql` — 테이블·뷰·집계 함수·보안(RLS). 1회 실행
- `supabase_seed.sql` — 매체 마스터 119종, 차량 마스터 10,451종 초기값. 1회 실행
- `index.html` — 웹 앱(로그인·업로드·광고비·매핑·대시보드·다운로드). 단일 파일

소요 시간: 약 35분 (1~4단계) + 데이터 업로드 10분
배포: GitHub Pages (파일 재업로드만으로 자동 재배포, 버전 이력·롤백 가능)

---

## 1. Supabase 프로젝트 만들기 (5분)

1. https://supabase.com 가입 → **New project**
   - Name: `marketing-db` (자유), Database Password: 안전한 비밀번호(메모), Region: **Northeast Asia (Seoul)**
   - Plan은 Free로 충분 (현재 데이터 약 25만 행 ≈ 150MB, Free 한도 500MB)
2. 생성 완료 후 왼쪽 메뉴 **Project Settings → API** 에서 두 값을 복사해 둡니다.
   - `Project URL` (https://xxxx.supabase.co)
   - `anon` `public` key (eyJ… 로 시작하는 긴 문자열)

## 2. SQL 실행 (5분)

1. 왼쪽 메뉴 **SQL Editor → New query**
2. `supabase_setup.sql` 내용을 전체 붙여넣고 **Run** → "Success" 확인
3. 새 쿼리를 열고 `supabase_seed.sql` 내용을 붙여넣고 **Run** (파일이 커서 10~20초 걸릴 수 있음)
4. 확인: **Table Editor** 에 `inquiries, sales, media_map, car_map, ad_spend, upload_batches` 6개 테이블이 보이고, `media_map`에 119행이 있으면 정상

> 다시 실행해도 안전합니다(이미 있는 것은 건너뜀). 구조를 바꿀 때도 같은 파일을 수정해 다시 Run 하면 됩니다.
> 데이터가 이미 들어 있는 상태에서 새 버전을 Run 했다면, 이어서 `select fn_refresh_agg();` 를 한 번 실행해 집계와 IP 중복 판정을 갱신하세요(최초 1회 30초~2분).

## 3. 로그인 계정 만들기 (3분)

1. **Authentication → Sign In / Providers**: `Email`이 ENABLED인지 확인(기본값). 같은 페이지 위쪽 "User Signups" 섹션의 `Allow new users to sign up`이 보이면 **끄기** → Save
   (외부인이 스스로 가입하지 못하게 막는 설정입니다. 항목이 없는 UI 버전이면 건너뛰어도 됩니다 — 앱에 가입 화면이 없습니다.)
2. **Authentication → Users → Add user → Create new user**: 팀원 이메일/비밀번호 입력, `Auto Confirm User` 체크 → Create. 팀원 수만큼 반복
   (`Auto Confirm`을 체크하면 확인 메일 없이 바로 로그인됩니다.)
3. **Authentication → URL Configuration** (4단계에서 배포 주소가 나온 뒤에 설정):
   - `Site URL`: `https://<아이디>.github.io/<저장소명>/`
   - `Redirect URLs` → Add URL: 같은 주소를 추가
   - "비밀번호 찾기" 메일의 링크가 이 주소로 돌아오게 하는 설정입니다. 빠지면 재설정 링크가 localhost로 가서 동작하지 않습니다.

### 활동 로그 (관리자 전용)
- 로그인·로그아웃·비밀번호 변경, 업로드, 배치 활성/비활성, 매체·차량 마스터 수정, 광고비 기입·수정·삭제, 집계 갱신이 계정별로 자동 기록됩니다(데이터 변경은 DB 트리거가 기록하므로 화면을 거치지 않아도 남습니다).
- `admin_users`에 등록된 이메일로 로그인하면 상단에 **로그** 메뉴가 보이고, 기간·계정·동작으로 조회·CSV 다운로드할 수 있습니다. 관리자가 아닌 계정은 메뉴가 보이지 않고 DB 차원(RLS)에서도 조회가 차단됩니다.
- 첫 관리자는 `supabase_setup.sql`의 `insert into public.admin_users` 줄에 적힌 이메일입니다. 이후 관리자 추가·제거는 로그 화면 하단에서 합니다.

### 계정 관리 요약
| 할 일 | 어디서 | 누가 |
|---|---|---|
| 계정 추가 / 삭제 | Supabase → Authentication → Users | 관리자 |
| 비밀번호를 잊음 | 앱 로그인 화면 → 이메일 입력 → **비밀번호 찾기** → 메일 링크 → 새 비밀번호 | 본인 |
| 비밀번호 변경 | 앱 로그인 후 **설정** 탭 → 비밀번호 변경 | 본인 |
| 강제 재설정 | Supabase → Users → 해당 사용자 `…` → Send password recovery | 관리자 |

> 재설정 메일은 Supabase 기본 발송 서버를 쓰며 시간당 발송 수 제한이 있습니다(소규모 팀에는 충분). 메일이 안 오면 스팸함을 확인하고, 자주 쓰게 되면 Authentication → Emails → SMTP Settings에 회사 메일 서버를 연결하면 제한이 없어집니다.

## 4. 웹페이지 배포 — GitHub Pages (10분)

GitHub Pages를 쓰는 이유: `index.html`은 앞으로 계속 수정될 파일입니다. GitHub에 올려 두면 **파일을 다시 업로드하는 것만으로 자동 재배포**되고, 누가 언제 무엇을 바꿨는지 이력이 남으며, 잘못 올렸을 때 이전 버전으로 되돌릴 수 있습니다. 터미널이나 Git 명령어는 필요 없습니다.

### 4-1. 접속 정보 넣기
`index.html`을 메모장(또는 VS Code)으로 열어 상단 두 줄에 1단계 값을 넣고 저장합니다.
```
const SUPABASE_URL      = "https://xxxx.supabase.co";
const SUPABASE_ANON_KEY = "eyJ...";
```
- URL은 **Project Settings → API → Project URL** 값으로, `https://프로젝트ref.supabase.co` 까지만 넣습니다(대시보드 주소 `supabase.com/dashboard/...` 아님, 뒤에 `/`나 경로 없음).
- key는 같은 화면의 `anon` `public` 키입니다(`service_role` 키는 절대 넣지 않음).
- 이 두 값은 파일에 고정되며, 사용자는 이메일·비밀번호만 입력해 로그인합니다.

anon key는 공개용 키라 페이지에 포함돼도 괜찮습니다. 접근 제어는 Supabase의 RLS(로그인 필수)가 담당하므로 **로그인 계정을 공유하지 않는 것**이 핵심입니다.

### 4-2. 저장소 만들고 올리기
1. https://github.com 가입 → 우측 상단 **+ → New repository**
   - Repository name: `marketing-db`
   - **Public** 선택 (GitHub Pages 무료는 Public 저장소만 가능. 코드 공개가 부담되면 아래 "대안" 참고)
   - **Create repository**
2. 생성된 빈 저장소 화면에서 **uploading an existing file** 링크(또는 **Add file → Upload files**) 클릭
3. `index.html`을 끌어다 놓기 → 하단 **Commit changes**
   - 같은 자리에 `supabase_setup.sql`, `supabase_seed.sql`, `적용가이드.md`도 함께 올려 두면 한곳에서 관리됩니다. (SQL 파일은 공개돼도 접속 정보가 없어 무방)

### 4-3. Pages 켜기
1. 저장소 상단 **Settings → 왼쪽 메뉴 Pages**
2. Build and deployment → Source: **Deploy from a branch**
3. Branch: **main**, 폴더: **/ (root)** → **Save**
4. 1~2분 후 같은 페이지 상단에 주소가 표시됩니다: `https://<아이디>.github.io/marketing-db/`
   (처음에는 404가 뜰 수 있습니다. 2~3분 기다렸다가 새로고침)
5. 이 주소를 팀원에게 공유. 각자 3단계에서 만든 계정으로 로그인

### 4-4. 이후 수정 반영 (매번 1분)
1. 수정된 `index.html`을 받으면 저장소 → **Add file → Upload files** → 파일 드래그 → **Commit changes**
2. 같은 이름이라 자동으로 덮어쓰기 되고, 1~2분 뒤 사이트에 반영됩니다 (브라우저에서 Ctrl+F5 새로고침)
3. 이전 버전으로 되돌리기: 저장소 **Commits**(시계 아이콘) → 되돌릴 시점의 커밋 → `index.html` → **Raw** 로 받아 다시 업로드

> **대안** — 저장소를 Private으로 두고 싶으면 **Cloudflare Pages**(비공개 GitHub 저장소도 무료 연동)를 쓰세요. GitHub 저장소는 같은 방식으로 만들고 Private 선택, Cloudflare 대시보드 → Workers & Pages → Create → Pages → Connect to Git → 저장소 선택 → Framework preset: None → Save and Deploy. 이후 수정 반영 방식은 동일합니다.
>
> **배포 없이 쓰기** — `index.html`을 더블클릭해 브라우저로 열어도 동작합니다. 급할 때 임시로 쓰고, 팀 공유는 GitHub Pages 주소로 하세요.

## 6. 매핑 작업 (처음 1~2시간, 이후 월 10분)

**매핑** 탭에서 두 마스터를 채웁니다. 원본 데이터는 건드리지 않고 이 표만 수정합니다.

**매체 마스터** (119종, 유입 광고매체 기준)
- `유형`: 마케팅 / 내부 / 경비 중 선택. 대시보드의 "매체유형 포함" 체크로 집계 포함 여부가 결정됩니다.
  - 마케팅: 광고·사이트·전화 등 마케팅 성과로 집계할 매체 전부 (`사이트-…`, `메타-…`, `플친-…`, `당근-…`, `대표전화-…`, `엔카` 등)
  - 내부: `지인(팀)`, `개인광고(팀)`, `추가계약`, `기존고객소개`
  - 경비: `정산전용💰` 계열 (SQL에서 기본 지정됨)
- `표준매체명`: 같은 매체를 다른 이름으로 쓴 경우 하나로 통일(광고비 입력 시 이 이름을 사용). 기본값은 원문 그대로.
- `플랫폼`·`브랜드`: 이름에서 자동 분리된 초깃값이 들어 있음(예: `사이트-KS오토플랜` → 사이트 / KS오토플랜). 브랜드별 요약은 이 `브랜드` 값으로 집계됩니다.
- 매출 raw의 유입매체 중 이 표에 없는 4종(`개인광고`, `사이트-KS신차장기렌트`, `사이트-카픽`, `플친-국민중고리스`)은 "미매칭 매출"로 분리되어 집계에서 제외되고, 다운로드 탭에서 따로 받을 수 있습니다.

**차량 마스터**
- 차량명 원문이 10,451종(자유 입력 텍스트)이며, 브랜드가 붙은 이름은 자동 분리되었고 브랜드 없는 모델명(`쏘렌토`, `EV5`, `Model Y` 등)은 모델명으로 브랜드를 추론해 `자동(모델명추론)`으로 표시했습니다. 현재 차량명이 입력된 유입의 87%, 매출의 92%에 브랜드가 지정된 상태입니다(유입 중 약 4만 건은 차량명이 공란·`-`라 브랜드 집계에서 "(없음)"으로 표시).
- 필터 `브랜드 미지정만`은 건수가 많은 순으로 나오므로 상위 100~200개만 채워도 커버리지가 95%를 넘습니다. 나머지 롱테일(오타·장난 입력)은 그대로 두어도 됩니다.
- `표준모델명`을 통일하면(예: `카니발`·`기아 카니발`·`더 뉴 카니발` → `카니발`) 차량별 집계가 합쳐집니다.

## 7. 광고비 입력 (브랜드 × 광고채널)

**광고비** 탭. 광고비는 유입 매체가 아니라 **자사 브랜드 × 광고채널** 단위로 기록합니다.
- 채널 12종: 네이버 파워링크 · 네이버 GFA · 카카오 키워드 광고 · 카카오 모먼트 · 카카오 친구톡 · 구글 애즈 · 메타 광고 · 틱톡 광고 · 당근 광고 · 블로그 인플루언서 · 유튜브 PPL · 기타
- 한 건씩: 일자 + 브랜드 + 채널 + 광고비(+노출·클릭) → 저장. 같은 키는 덮어쓰기.
- 월 단위 일괄: "양식 월"과 브랜드(단일·복수)를 고르고 **양식 다운로드** → 컬럼 `일자 · 브랜드 · (채널 12개) · 메모`, 선택한 브랜드와 날짜가 미리 채워진 CSV. 채널 칸에 금액만 적어 **업로드**. 빈 칸은 건너뜀. "브랜드별 파일 각각"을 고르면 브랜드마다 파일이 따로 내려옵니다.
- 브랜드 이름은 매체 마스터의 브랜드와 같아야 브랜드별 ROAS·CPA에 연결됩니다. 광고비는 브랜드 단위라 **매체별 표에는 광고비·ROAS·CPA가 없고 브랜드별 표에 있습니다.** 대시보드 브랜드별 요약 아래에 "브랜드 × 광고채널 광고비" 표가 함께 나옵니다.
- Meta·Google Ads·Kakao·네이버 자동 수집은 같은 테이블(`ad_spend`)에 브랜드·채널로 넣는 스크립트만 추가하면 됩니다.

## 8. 지표 정의 (대시보드)

| 지표 | 계산 | 비고 |
|---|---|---|
| DB(전체) / DB(제외후) | 유입 행 수 / 중복 제외 체크박스 적용 후 행 수 | 체크박스 2개: **CRM 중복**(중복여부=Y) · **IP 중복**(같은 IP로 7일 내 재문의, IP는 해시로만 저장, 사설IP 제외). 원본은 삭제되지 않고 집계에서만 빠짐. CPA·전환율은 제외후 기준 |
| 계약수 / 매출 / 차량가 합계 | 활성 배치의 매출 행 수 / **계약마진 합계** / 차량가격 합계(참고) | 유입 매체와 매칭된 행만. 매출 = 계약마진 |
| ROAS | 매출(계약마진) ÷ 광고비 | 브랜드 단위(광고비가 브랜드×채널 기준). 매체별 표에는 없음 |
| CPA(DB) / CPA(계약) | 광고비 ÷ DB수 / 광고비 ÷ 계약수 | 브랜드 단위 |
| 전환율 | 계약수 ÷ DB수 | 같은 기간 집계 비교(코호트 아님) |
| 리드타임 | 계약일자 − 문의일자 | 음수·1년 초과·경비 유형 제외, 중앙값 함께 표시 |
| 매출 기준일 | 계약일자(재무 보고) 또는 문의일자(광고 코호트 비교) | 필터에서 선택 |

현재 데이터 기준 참고치: 2026-01~09 정상 계약 9,258건, 리드타임 중앙값 2일 / 평균 15.5일 / 7일 이내 68%. 계약일자 역전(음수) 167건, 1년 초과 131건은 분포 차트에 "제외" 막대로 표시되며 삭제되지 않습니다.

## 9. 문제가 생기면

| 증상 | 조치 |
|---|---|
| 로그인 실패 | Authentication → Users 에서 계정 존재·Confirmed 확인. 비밀번호 재설정은 Users 목록에서 가능 |
| "permission denied" 오류 | `supabase_setup.sql` 을 다시 Run (권한·RLS 재적용) |
| 업로드 중 중단 | 이미 저장된 행은 유지됨. 유입은 같은 파일을 다시 올리면 됨(갱신). 매출은 실패한 배치를 비활성화 후 다시 업로드 |
| 대시보드 조회가 느림(5초 이상) | 추이 단위를 주/월로. 데이터가 100만 행을 넘으면 Supabase Pro 또는 집계 테이블 추가 검토 |
| 지표 정의를 바꾸고 싶음 | `supabase_setup.sql` 의 `fn_media_period` 등 함수만 수정해 다시 Run. 화면 수정 불필요 |
| 컬럼 구조가 바뀐 엑셀 | 검증 단계에서 "알 수 없는 컬럼"으로 표시되고 raw(JSON)에 보존됨. 필수 컬럼(문의번호·문의일시·광고매체 / 유입매체·문의일자·계약일자·차량가격)만 있으면 업로드 가능 |
